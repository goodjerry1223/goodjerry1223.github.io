π₀.₅ 通过 Action Chunking 实现低频视觉推理和高频动作控制。模型推理时通常一次预测未来 50 步动作，Flow Matching 采用 10 次积分，完成后将整个动作序列交给仿真环境执行。

在 RoboTwin 原生配置中，SAPIEN 物理仿真步长为 0.004s，对应 250Hz；默认每 15 个物理步采集一次示教数据，数据频率约为 16.67Hz。评估时每个 VLA 动作经 TOPP／规划后可能执行不同数量的物理步。50 个动作的仿真时长也就是仿真执行中VLA视觉输入的更新频率应为“各次 take_action() 实际 scene.step() 次数之和 × 0.004 s”

π₀.₅ 在 RoboTwin 中的动作执行与控制

π₀.₅ 的 Action Chunk 如何交给 RoboTwin 执行？

π₀.₅ 一次推理输出一个 Action Chunk，例如 50×14，包含未来 50 步的双臂关节与夹爪动作。

经过反归一化和动作格式转换后，逐步调用 RoboTwin 的 take_action()：

  • qpos 模式：直接提供目标关节位置。

  • ee 模式：提供末端位置和姿态，通过 IK/运动规划转换为关节轨迹。

RoboTwin 如何将 Action 转换为关节力矩？

RoboTwin 使用 SAPIEN/PhysX 的关节驱动器，基本控制机制为 PD 位置控制 + 动力学补偿。

τ_PD = K_p(q_d - q) + K_d(q̇_d - q̇)

其中 q_d 是目标关节角，q 是实际关节角。

物理引擎将驱动力矩与重力、惯性、摩擦、接触力等共同纳入动力学求解，计算下一时刻的关节位置与速度。

因此，Policy 输出的是控制目标，PhysX 才负责物理运动。

RoboTwin 是否存在轨迹跟踪误差？

存在。因为 PD 控制不保证实际位置完全等于目标位置。

主要来源包括：

  • 动态滞后：目标变化过快，机械臂无法立即跟随。

  • 控制器误差：刚度、阻尼及力矩限制使跟踪不完全。

  • 接触扰动：抓取、碰撞、插拔时外力改变机械臂运动。

  • 离散化误差：有限物理步长、求解器精度造成偏差。

可以定义：

e_q(t) = q_d(t) - q(t)

末端位置误差近似满足：

Δx ≈ J(q)Δq

RoboTwin 有没有考虑重力前馈？

RoboTwin envs/robot/robot.py 中实现了：

def _entity_qf(self, entity):
    qf = entity.compute_passive_force(
        gravity=True,
        coriolis_and_centrifugal=True
    )
    entity.set_qf(qf)

set_arm_joints() 会调用 _entity_qf()，再下发关节位置和速度目标。

因此控制机制可以近似理解为：

τ = τ_PD + τ_gravity + τ_coriolis

即 PD + 重力补偿 + 科氏力/离心力补偿。

IK 解决的是目标位姿有没有可行的关节解

仿真步长和“小 Action”如何定义？对轨迹有什么影响？

需要区分三个概念：

例如，假设控制频率为 50 Hz：

Δt_control = 0.02 s

如果相邻两个关节位置命令相差 0.01 rad，相当于目标关节速度约为：

q̇_d ≈ 0.01 / 0.02 = 0.5 rad/s

因此

  • 动作增量过大：相邻目标发生跳变，容易出现跟踪滞后、过冲和碰撞冲击。

  • 动作增量较小：目标轨迹通常更平滑，但并不自动保证准确，且需要更多控制步完成相同位移。

  • Physics Step 过大：可能降低接触仿真的时间分辨率和求解稳定性。

  • Physics Step 较小：一般有利于数值精度，但增加计算开销。

RoboTwin 与 LIBERO 常见仿真平台

其中最重要的区别是 RoboTwin 与 LIBERO：

  • RoboTwin 的典型 qpos 模式：π₀.₅ 直接输出关节目标，由 PhysX Drive 跟踪。

  • LIBERO 默认模式：Policy 输出末端位姿增量，由 OSC 根据末端位姿误差、Jacobian 和动力学模型计算关节力矩，不需要先对每个目标执行 IK。

  • Isaac Lab：支持显式建模电机力矩限制、延迟等，更方便研究底层控制器和执行器误差。

LIBERO 官方默认控制频率为 20 Hz，控制器为 OSC_POSE。

1. 什么是轨迹跟踪误差

轨迹跟踪误差是在同一执行时刻比较控制器下发的参考轨迹与机器人实际状态：

e_q(t) = q_ref(t) - q_actual(t)，e_q̇(t) = q̇_ref(t) - q̇_actual(t)

任务更关心末端时，还应记录位置误差和姿态误差。文档中的 Δx ≈ J(q)Δq 是小误差附近的近似，适合解释关节误差如何传到末端。

2. 动力学补偿能消除多少误差

RoboTwin 在 set_arm_joints() 中计算重力、科氏力和离心力对应的被动力补偿，并通过 set_qf() 施加；随后设置关节位置和速度目标。SAPIEN 的 drive 依据刚度、阻尼追踪目标。

补偿能消除的是模型所描述的那部分负载。理想静止、模型准确且未饱和时，重力前馈可以消除 PD 为平衡重力而产生的稳态偏差；运动中的惯性需求、接触力、模型误差、驱动饱和和离散控制仍会带来误差。

3. VLA 的 action chunk

在当前 RoboTwin take_action() 中：

  • qpos****：每次调用只接收一个目标。代码以当前 drive target 和该目标组成两点路径，分别对左右臂调用 MPlib TOPP()，再按 250 Hz 下发生成的位置、速度序列。MPlib 的这一路 TOPPRA 实现施加关节速度和加速度约束；未在此处施加 jerk、力矩或路径碰撞约束。TOPP 失败时，代码仍推进 50 个仿真步，并保留该侧先前的手臂驱动目标。

  • **ee****：每个末端目标先经过抓取参考位姿到规划末端连杆的坐标变换，再调用规划器；**RoboTwin 的 cuRobo 路径取规划成功后的插值关节位置和速度执行。规划器可以检查其配置中的运动学与碰撞条件，但这仍不等于实机力矩和跟踪安全保证。

4. 是否需要进一步处理 action chunk

把 VLA 输出视为目标序列，经过以下执行链：

反归一化与单位/坐标系核对 → 有限值和关节/夹爪范围检查 → 按实际反馈状态接入首点 → 路径与双臂碰撞检查 → 时间参数化或轨迹优化 → 在控制周期上采样 → 速度/加速度/jerk/力矩与末端误差验证 → 执行并监测反馈

对 ee pose，还要检查四元数归一化、姿态插值、IK 分支连续性、奇异位形及工具中心点与规划末端连杆的变换。对连续 chunk，要核对边界处的位置、速度、加速度连续性；

5. Ruckig、cuRobo 轨迹

工具 实际机制 能保证或检查的范围
Ruckig 从当前 q、q̇、q̈ 到目标状态在线生成轨迹，输入逐轴速度、加速度、jerk 上限，可同步多轴并按控制周期取样。 对有效输入生成满足所设运动学限制的状态轨迹；Community 版的中间路点使用云端接口，位置限位和 Tracking 接口属于 Pro 功能。
cuRobo 通过轨迹优化惩罚加速度、jerk，并结合关节界限、碰撞代价、时间步优化和插值轨迹评估，选择成功轨迹。 适合生成并评估配置约束下的关节路径；平滑代价与插值评估应查看实际参数和输出结果。RoboTwin 调用的是其规划结果。
RoboTwin qpos 路径中的 TOPPRA 沿两点关节路径按速度、加速度限制重新定时。 当前这条调用没有 jerk 与力矩约束；它也没有把整个 VLA chunk 作为一条统一轨迹优化。

关于 Ruckig 工具：

Ruckig 是一款用于在线轨迹生成（OTG）的高效库。它的核心优势在于能够严格满足速度、加速度以及加加速度（Jerk）的物理上限约束。

  • 在机制上：它接收当前的运动状态（q, q˙q˙, q¨q¨）和目标状态，能在极短的时间内实时计算出平滑的多轴同步轨迹。

  • 在 VLA 仿真链路中：它相当于“动作平滑器”。虽然 VLA 输出了连续的动作块，或 cuRobo 规划出了空间路径，但为了确保物理引擎（SAPIEN）中的电机不发生剧烈抖动或过载，底层往往会通过 Ruckig 对这些路径进行时间重采样（重定时），生成满足动力学限制的平滑轨迹。
